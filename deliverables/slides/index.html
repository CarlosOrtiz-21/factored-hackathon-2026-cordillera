04 · Safety by designControls enforced in code

Safety lives in the code path, not in the prompt.

01
Golden rule
No side effect before a human
Agents hold read tools only. A block is a proposal; a deterministic node runs it after approval, then re-reads the card.
02
Approval gate
The gate is a line of code
is_write(action) or risk > 0.7
The critic's risk score is a signal; the rule is the barrier.
03
Segregation of duties
The requester can't approve
Auditor role required, approver ≠ requester, approver id taken from the auditor's token. Approvals expire in 10 minutes.
04
Privacy
The LLM never sees raw PII
Presidio + custom recognizers (cards, CC, NIT, CURP, DNI, emails). Only 9.98% of dataset card numbers pass Luhn, so any 15–16 digits are tokenized.
05
Ownership
Customers only see their own cards
Every tool checks the session owns the card. Another customer's card answers "not found", so nothing can be enumerated.
06
Abuse & cost
Injections refused, spend capped
Injection regex (dev set 34/34, 0 false positives) plus LLM triage; poisoned documents treated as data; a daily API budget cap on the public demo.
